# 2. Add Two Numbers

<https://leetcode.com/problems/add-two-numbers/>

## Step1

- 方針としてはループで回しながら2つの要素を足していき新しいリンクトリストを作成する
- l1かl2を書き換えていく案も考えたが、どちらか1方のリストを書き換えるという副作用がある関数はユーザーフレンドリーではないと感じた
  - メモリが限られているという要件が明確にある場合にのみ検討するのでも遅くないと考え、新しいリストを作成する方針とした
- 82/83/141/142をすでに実施していたため、ある程度実装の方法が頭にあり、20分くらいでPassすることができた
- 変数名は少し悩んだが以下のような気持ちで命名した
  - dummy
    - 番兵パターンのダミー要素
  - tail
    - 返却するリストの最後の要素
  - carry
    - 桁上がり
  - n{1|2}
    - l{1|2}の現在のノード
    - node{1|2}やcurrent{1|2}と悩んだが、より直感的なnodeが個人的にはしっくりきたのと、goの慣習(変数を短く略す)に従いn{1|2}を採用
      - 参考: <https://github.com/riku359/LeetCode/pull/9#discussion_r2638341640>
- carryについては`bool`にする案も一瞬考えたが、やや可読性が上がる可能性があるくらいしかメリットが思いつかず、直接的に扱える`int`を採用した

## Step2

- 他の人のPRや、AIを使って3種類の方法で実装
  - addTwoNumbers_2
    - step1.goを少しリファクタした実装
    - `if carry != 0 {...`の分岐をforの条件に加えてシンプルになった
  - addTwoNumbers_2_recursive
    - 再起を使った実装
  - addTwoNumbers_2_iter
    - イテレーターを使った実装
- 3つを比較すると、以下の理由から`addTwoNumbers_2`が良さそう
  - 再帰はスタックにフレームが積み重なる
  - また、再帰の空間計算量は`addTwoNumbers_2`と変わらない(O(max(m,n)))が、実際にベンチマークをとったところ1.6倍程度遅いことが確認できた
    - おそらくスタックの伸長処理によるもの
  - イテレーターを使った実装は、コード量が増え可読性が低いと感じた
