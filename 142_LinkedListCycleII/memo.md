## Step2

- Floydの循環検出のロジックで挑戦
  - 循環を検出するところまでは実装できたが、循環を検出=循環の入り口だと勘違いしてそのまま提出するもNG
  - 循環を検出してから循環の入り口を求める方法がわからずAIや過去のDiscordを色々調べながら実装し、提出してOK

```txt
step2.go の第1フェーズは正しく書けています。詰まっているのは「出会った地点＝循環の入口ではない」という点です。return fast だと出会った地点をそのまま返してしまうので、ここから入口を求める第2フェーズが必要です。

なぜ head に戻すと入口で会えるのか

距離を次のように置きます。

        a              b
head ──────► 入口 ──────► 出会った地点
              ▲                │
              └────────────────┘
                     c            （循環長 L = b + c）

- slow が進んだ距離: a + b
- fast は slow の2倍進んでいて、循環を何周か余分に回っているので: 2(a + b) = a + b + kL（k ≥ 1）

整理すると

a + b = kL
a     = kL - b = (k-1)L + (L - b) = (k-1)L + c

つまり 「head から入口までの距離 a」は「出会った地点から入口までの距離 c」に、循環を (k-1) 周足したもの。周回分は循環の中をぐるっと回るだけで位置は変わらないので、

- head から 1歩ずつ進むポインタ
- 出会った地点から 1歩ずつ進むポインタ

を同時に動かすと、ちょうど 入口で一致 します。fast/slow の 2:1 が効くのは第1フェーズだけで、第2フェーズは両方とも 1歩ずつです。
```
