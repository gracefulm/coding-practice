# 1. Two Sum

<https://leetcode.com/problems/two-sum/description/>

## Step1

- 全ての組み合わせを確認してtargetと一致する組み合わせが見つかったら、そのインデックスを返す
- 計算量
  - 時間計算量: O(n^2)
  - 空間計算量: O(1)
- 実行時間の見積もり
  - 内側のループは `j = i+1` から始まるので、比較回数は (n-1) + (n-2) + ... + 1 = n(n-1)/2 回 (= nC2)
  - n <= 10^4 なので、最悪ケースで 10^4 × (10^4 - 1) / 2 ≈ 5×10^7 回
    - O記法では係数1/2と低次の項を捨てるのでO(n^2)だが、実際の回数はn^2(10^8)の約半分
  - Goは1秒あたりおよそ10^8〜10^9回の単純な演算ができるので、数十ms程度で終わる見込み

## Step2

### nestedloop

- Step1のコードを読みやすく整えた
  - 内側を `for j := i + 1; j < len(nums); j++` の添字ループにして、`i + 1 + j` のインデックス計算をなくした
  - `nums[:len(nums)-1]` のスライスをやめたので、`len(nums) < 2` のガードが不要になった（空でも長さ1でもループが回らずに `nil` を返す）
  - 条件式を `nums[i]+nums[j] == target` の自然な順序にした
- 計算量はStep1と同じ
  - 時間計算量: O(n^2)
  - 空間計算量: O(1)

### hashmap

- 値→インデックスのmapを持ち、1回の走査で `target - num` がすでに出てきているかを調べる
  - 先に相方を探してから自分を登録する順番にすることで、同じ要素を2回使わずに済み、`[3,3]` のような重複にも対応できる
- 計算量
  - 時間計算量: O(n)（mapの検索・追加は平均O(1)）
  - 空間計算量: O(n)
- 実行時間の見積もり
  - n <= 10^4 なので、mapの操作は最大で検索・追加それぞれ約10^4回
  - 実測（Apple M2 / Go 1.26.2、要素数10^4）では、読み込みが約10ns、書き込みが約11ns（容量指定あり）〜35ns（指定なし）
    - 容量指定あり: 10^4 × (10 + 11) ns ≈ 0.2ms
    - 容量指定なし: 10^4 × (10 + 35) ns ≈ 0.45ms
  - nestedloop（数十ms）より100倍前後速い
- `make(map[int]int, len(nums))` のように容量を指定すると、要素追加時のmapの拡張（再ハッシュ）を避けられる
  - 実測では書き込みが約3倍速くなった
  - 詳しくは [notes/go-make-and-map.md](../notes/go-make-and-map.md)

### 比較

- 時間を取るならhashmap、メモリを節約するならnestedloop
- 配列を順に読むだけの二重ループは1回あたりのコストが小さいので、nが小さいうちはnestedloopの方が速いこともある
